## Playback modes

All modes use one asynchronous VAE→JPEG encoder, one paced encoded queue and the
existing localhost frame bridge. The modes are explicitly selected:

- `fixed` (default, legacy C7): send **every** frame at `--output-fps`. Bounded
  queue applies backpressure. May grow many seconds behind live generation.
- `smooth`: send **every** frame, adjust pacing rate between
  `--min-playback-fps` and `--max-playback-fps` in small steps at ~1s cadence
  according to buffered frame count. A 5→8 FPS proposal, *not* a measured
  improvement. Backpressure remains bounded and lossless; smooth playback may
  be substantially behind real time.
- `interactive`: prioritize the most recently generated frames. When its
  bounded queue fills, evict oldest not-yet-played JPEG frames. Skip frames
  that have waited beyond `--max-frame-age-ms` if fresher frames exist. The
  latest frame is always eligible. Sequence numbers remain **monotonically
  increasing but may have gaps** by design. The Quest viewer may show jumps.
  This is experimental low-latency policy, *not* a proven <2s E2E path.

```bash
# Stable baseline: 5 FPS, lossless, unchanged C7 behavior

  --output-fps 5 --playback-mode fixed \

# Smooth: experiment with a 5–8 FPS rate range, no dropping

  --output-fps 5 --playback-mode smooth --max-playback-fps 8 \
  --target-buffer-ms 700 \
  --work-dir /root/autodl-tmp/bench/c72-smooth
# Interactive: deliberate skips for a fresher view; shorter queue

  --output-fps 5 --playback-mode interactive --max-playback-fps 8 \

```

Runs must be **sequential**, as all use cloud port `8766`; do not overwrite
C5 `8765` or Mac's C5 `18765`. `--max-segments 0` continuously incurs GPU cost;
use bounded 3-segment runs for first tests. Retain known-good C7 branch for
rollback if new options do not work.

## Read metrics over the existing 18766 Mac tunnel

The opt-in `GET /v1/metrics` returns a snapshot of:

- `bridge`: legacy `state`, `sequence`, `ptsMs`, `ageMs`
- `playback`: `mode`, `currentFps`, `mediaTimebaseFps`, `queueDepth`,
  `oldestQueueAgeMs`, `published`, `droppedFrames`, `droppedByAge`,
  `underflowEvents`, `averagePublishedFps`, `maxPublishedFrameAgeMs`
- `encoder`: `rawQueueDepth`, `rawQueueMaxDepth`, `rawQueueBlockedSec`,
  `timingTotalFrames`, `timingWindowFrames`, rolling timing percentiles
- `completedSegments` and `framesPerSegment`

Old `GET /v1/status` and `GET /v1/frame.jpg` formats are **unchanged**;
old bridges without a metrics provider return 404 for `/v1/metrics`.
`TimingStats` retains only the last **512** frame timing samples, while
keeping a cumulative count, to avoid unbounded observability memory growth.

```bash
curl -fsS http://127.0.0.1:18766/v1/metrics
python scripts/collect_quest_playback_metrics.py \
  --url http://127.0.0.1:18766 \
  --duration 120 --interval 1 \
  --out /Volumes/ssd/qps-local-builds/c72-3mode-samples.jsonl
```

The collector only accepts localhost HTTP URLs; when the tunnel/bridge is
closed, it records errors rather than silently claiming valid metrics.
`oldestQueueAgeMs` and `maxPublishedFrameAgeMs` measure age **since JPEG enters
the encoded queue**; they do *not* include DiT, VAE, cloud→Mac transfer,
WebRTC encoding/decoding or Quest presentation time. No E2E latency claim can
be made until Mac/Quest telemetry is instrumented and clock alignment is
addressed. With changing pacing FPS, media PTS remains monotonic at the
original `--output-fps` nominal timebase, not wall-clock playout time.

## Acceptance gates on a future joint test day

1. **CPU (now):** fixed-mode no regressions, smooth rate clamp/hysteresis,
   interactive monotonic skip semantics and bounded queue, real localhost HTTP
   metrics, bounded 512-sample encoder statistics, worker error reporting.
2. **GPU (later):** three 125-frame segments at fixed/smooth/interactive with
   4090. Compare generated FPS vs. *actual* published FPS, queue age,
   underflows, drops, memory, VAE/JPEG timings and C7 segment boundaries.
   Also test 253-frame segments and repeat 10–30-minute bounded stress runs.
3. **Quest (later):** install the landscape APK, connect Mac Sender to
   `http://127.0.0.1:18766`, visually assess motion continuity/lag and ensure
   WebRTC remains connected when dropping encoded frames. Measure actual
   headset presented FPS and latency before choosing a shipping default.

**Expected trade-off:** smooth may become more responsive if generation can
keep up, but can drift behind; interactive may improve freshness with skips.
Neither promise is proven by CPU tests. If new modes regress, launch without
`--playback-mode` to use the original fixed strategy.
